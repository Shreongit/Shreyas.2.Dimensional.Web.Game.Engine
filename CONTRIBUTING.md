# Contributing

## Before opening a pull request

1. Keep public APIs documented and backward-compatible where practical.
2. Add or update tests for bug fixes and features.
3. Run `npm run ci` with Node.js 18 or newer.
4. Avoid adding runtime dependencies without explaining the trade-off.
5. Include reproduction steps for bug reports and browser/version details for rendering issues.

## Bug reports

Include browser and OS versions, expected behavior, actual behavior, console output, a minimal reproduction, and whether the issue occurs in the included demo.

## Pull requests

Keep changes focused. Describe behavior changes and known limitations. Do not label a change production-ready based only on syntax checks or unit tests.
